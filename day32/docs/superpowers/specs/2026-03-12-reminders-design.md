## Цель

Добавить в CLI-агент систему напоминаний на базе MCP-инструментов с отложенным выполнением, хранением данных в JSON и уведомлениями в интерфейсе.

---

## Архитектура

### Поток данных

```
Пользователь: "напомни через 30 минут выпить воду"
    ↓
LLM вызывает create_reminder(text, minutes) через MCP
    ↓
MCP-сервер: сохраняет в .reminders/data.json + запускает setTimeout
    ↓
[N минут спустя...]
    ↓
Chat.tsx (setInterval каждые 10с) вызывает check_fired_reminders()
    ↓
Агент показывает: 🔔 Напоминание: выпить воду
```

### Два пути создания напоминаний

1. **Через LLM** — пользователь пишет агенту на естественном языке, LLM вызывает MCP-инструмент
2. **Через CLI-команду** — пользователь вводит `/remind "текст" 30` напрямую

## Хранение данных

Файл: `.reminders/data.json` (путь относительно `process.cwd()` CLI-процесса)

```json
{
  "reminders": [
    {
      "id": "uuid-v4",
      "text": "выпить воду",
      "createdAt": "2026-03-12T10:00:00.000Z",
      "scheduledAt": "2026-03-12T10:30:00.000Z",
      "status": "pending"
    }
  ]
}
```

### Статусы напоминания

| Статус | Описание |
|--------|----------|
| `pending` | Ожидает срабатывания |
| `fired` | Время пришло, ещё не показано пользователю |
| `shown` | Показано пользователю |
| `cancelled` | Отменено |

## MCP-инструменты

### `create_reminder`
- **Входные параметры:** `text: string`, `minutes: number` (целое, > 0)
- **Действие:** Генерирует UUID, создаёт запись в JSON со статусом `pending`, запускает `setTimeout`
- **Возвращает:** `id`, `scheduledAt`

### `list_reminders`
- **Входные параметры:** нет
- **Действие:** Читает JSON, возвращает все напоминания
- **Возвращает:** Список напоминаний: id, text, scheduledAt, status

### `check_fired_reminders`
- **Доступ:** Только для внутреннего polling из Chat.tsx. **Не экспонируется LLM** (не входит в список инструментов, отображаемых агенту).
- **Входные параметры:** нет
- **Действие:** Ищет записи со статусом `fired`, атомарно меняет на `shown`, сохраняет JSON
- **Возвращает:** Массив сработавших напоминаний (может быть пустым)
- **Идемпотентность:** Второй вызов вернёт пустой массив, т.к. статус уже `shown`

### `cancel_reminder`
- **Входные параметры:** `id: string`
- **Действие:** Вызывает `clearTimeout` из `Map<id, NodeJS.Timeout>`, меняет статус на `cancelled`
- **Возвращает:** Подтверждение или ошибку, если ID не найден / статус уже не `pending`

## CLI-команда `/remind`

| Команда | Действие |
|---------|----------|
| `/remind` | Показать список всех напоминаний |
| `/remind <минуты> <текст>` | Создать напоминание (минуты — первый аргумент, целое число) |
| `/remind cancel <id>` | Отменить напоминание по ID |

### Валидация и ошибки

- Минуты не число → `Ошибка: укажите количество минут числом`
- Минуты ≤ 0 → `Ошибка: минуты должны быть больше 0`
- ID не найден → `Ошибка: напоминание не найдено`
- Текст пустой → `Ошибка: текст напоминания не может быть пустым`

## Polling в Chat.tsx

- `setInterval` каждые 10 секунд вызывает `check_fired_reminders()` через MCP-клиент
- Polling запускается только при активном MCP-соединении (`mcpManager.isConnected()`)
- Флаг `isPolling: boolean` предотвращает параллельные вызовы: если предыдущий запрос ещё не завершился, тик пропускается
- При срабатывании — выводит системное сообщение с `🔔`
- Polling останавливается при `/mcp disconnect`

## Поведение при перезапуске

При старте MCP-сервера:
1. Загрузить `.reminders/data.json` (если файл отсутствует — создать пустой)
2. Для каждого `pending`-напоминания пересчитать оставшееся время (`scheduledAt - now`)
3. Если `remainingMs <= 0` — установить статус `fired` и сохранить
4. Иначе — запустить `setTimeout(remainingMs)` и добавить хэндл в `Map`

## Ограничения

- Напоминания живут только пока запущен MCP-сервер (дочерний процесс агента)
- Только одиночные (one-shot) напоминания — повторяющихся нет
- Путь хранения зависит от рабочей директории запуска CLI
