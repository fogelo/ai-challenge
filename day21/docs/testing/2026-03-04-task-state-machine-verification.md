## Тестовые сценарии

### Сценарий 1: Автоматическое создание задачи
**Шаги:**
1. Запустить `npm start`
2. Ввести сообщение: "Напиши REST API для управления задачами"

**Ожидаемый результат:**
- ✅ Появляется уведомление "📋 Создана новая задача"
- ✅ Индикатор состояния показывает `[State: PLANNING] 🟡`
- ✅ В системном промпте появляются инструкции для состояния PLANNING

### Сценарий 2: Команды управления задачами
**Шаги:**
1. Ввести `/task` - показать текущую задачу
2. Ввести `/task new Создать систему авторизации`
3. Ввести `/task list` - список задач
4. Ввести `/task load 1` - загрузить первую задачу

**Ожидаемый результат:**
- ✅ `/task` отображает информацию о текущей задаче
- ✅ `/task new` создает новую задачу с указанным описанием
- ✅ `/task list` показывает список с индикаторами состояний
- ✅ `/task load` загружает выбранную задачу

### Сценарий 3: Переход между состояниями
**Шаги:**
1. Создать задачу (автоматически при первом сообщении)
2. Проверить текущее состояние: PLANNING 🟡
3. Ввести `/next` - переход к EXECUTION
4. Проверить изменение индикатора: EXECUTION 🔵
5. Ввести `/next` - переход к VALIDATION
6. Проверить индикатор: VALIDATION 🟠
7. Ввести `/next` - переход к DONE
8. Проверить индикатор: DONE 🟢
9. Попытаться ввести `/next` снова

**Ожидаемый результат:**
- ✅ Каждый `/next` успешно переводит в следующее состояние
- ✅ Индикатор обновляется корректно
- ✅ Отображаются инструкции для нового состояния
- ✅ В состоянии DONE команда `/next` сообщает о финальном состоянии

### Сценарий 4: Пауза и возобновление
**Шаги:**
1. Создать задачу
2. Перевести в состояние EXECUTION
3. Нажать Ctrl+C (пауза)
4. Запустить `npm start` снова
5. Ввести `/resume` - посмотреть список сессий
6. Проверить, что в списке отображается состояние задачи
7. Ввести `/resume 1` - восстановить сессию
8. Проверить, что индикатор показывает EXECUTION 🔵

**Ожидаемый результат:**
- ✅ Сессия сохраняется с taskStateId
- ✅ В списке `/resume` отображается `[EXECUTION 🔵]`
- ✅ После восстановления индикатор показывает правильное состояние
- ✅ Агент продолжает с нужного этапа без повтора вопросов

### Сценарий 5: Инъекция промпта
**Тестирование:**
- Создать задачу
- Проверить, что в системном промпте появляется блок:
  ```
  === ТЕКУЩЕЕ СОСТОЯНИЕ ЗАДАЧИ ===
  Задача: [описание]
  Текущий этап: PLANNING 🟡
  Что делать: [инструкции]
  История переходов: START → planning
  ===
  ```

**Ожидаемый результат:**
- ✅ Промпт инъецируется в системное сообщение
- ✅ Агент следует инструкциям для текущего состояния
- ✅ В PLANNING агент задает вопросы, не начинает выполнение
- ✅ В EXECUTION агент реализует план
- ✅ В VALIDATION агент проверяет результат

## Обнаруженные проблемы

### 1. TypeScript тип predicate (исправлено)
**Проблема:** Конфликт типов в session.ts при фильтрации null значений
**Решение:** Изменен type predicate с `session is SessionMetadata` на `session is NonNullable<typeof session>`
