# Task State Machine - Руководство пользователя

## 📋 Что это?

Task State Machine — это система формализованного управления состоянием задач в AI агенте. Агент автоматически проходит через этапы выполнения задачи и помнит, на каком этапе остановился.

## 🎯 Состояния задачи

Каждая задача проходит через 4 состояния:

| Состояние | Индикатор | Что делает агент |
|-----------|-----------|------------------|
| **PLANNING** | 🟡 | Задает вопросы, уточняет требования, составляет план |
| **EXECUTION** | 🔵 | Выполняет утвержденный план, пишет код |
| **VALIDATION** | 🟠 | Проверяет результат, предлагает тесты |
| **DONE** | 🟢 | Задача завершена, подводит итоги |

## 🔄 Переходы между состояниями

```
START → PLANNING → EXECUTION → VALIDATION → DONE
             ↓           ↓           ↓
             └───────────┴───────────┘
```

**Разрешенные переходы:**
- PLANNING → EXECUTION (план утвержден)
- EXECUTION → PLANNING (нужны изменения в плане)
- EXECUTION → VALIDATION (код готов к проверке)
- VALIDATION → EXECUTION (нужны доработки)
- VALIDATION → DONE (все работает)

**Недопустимые переходы блокируются!** Нельзя перепрыгнуть этапы.

## 🚀 Быстрый старт

### 1. Автоматическое создание задачи

Просто начните разговор — задача создастся автоматически:

```bash
npm start

> Напиши REST API для управления задачами
```

**Что произойдет:**
```
📋 Создана новая задача
Состояние: PLANNING 🟡
Начинаем планирование...

[State: PLANNING] 🟡 >
```

Агент автоматически:
- Создаст задачу в состоянии PLANNING
- Начнет задавать уточняющие вопросы
- НЕ будет писать код до утверждения плана

### 2. Прохождение через этапы

**PLANNING (Планирование)** 🟡

```
[State: PLANNING] 🟡 > Используй Express.js и TypeScript
```

Агент задаст вопросы:
- Какие endpoints нужны?
- Какая база данных?
- Нужна ли аутентификация?

Затем составит план.

**Переход в EXECUTION**

```
[State: PLANNING] 🟡 > Утверждаю план, начинай
```

Или используй команду:
```
[State: PLANNING] 🟡 > /next
```

**Что произойдет:**
```
✅ Переход: PLANNING → EXECUTION 🔵
Этап выполнения. Реализую план...

[State: EXECUTION] 🔵 >
```

**EXECUTION (Выполнение)** 🔵

Агент пишет код согласно плану:
```typescript
// Код REST API...
```

**Переход в VALIDATION**

```
[State: EXECUTION] 🔵 > Проверь результат
```

Или:
```
[State: EXECUTION] 🔵 > /next
```

**VALIDATION (Проверка)** 🟠

Агент проверяет код, предлагает тесты:
```
Проверяю код...
✅ Endpoints работают
✅ Обработка ошибок добавлена
💡 Предлагаю добавить unit-тесты
```

**Переход в DONE**

```
[State: VALIDATION] 🟠 > Все работает отлично
```

**DONE (Завершено)** 🟢

```
✅ Задача завершена! 🎉
Итоги: Создан REST API с 5 endpoints...

[State: DONE] 🟢 >
```

## ⏸️ Пауза и восстановление

### Сделать паузу

В любой момент нажмите:
```
Ctrl+C
```

Состояние задачи автоматически сохранится.

### Восстановить сессию

```bash
npm start

> /resume
```

**Вы увидите:**
```
📋 Сессии:
1. REST API для задач [EXECUTION 🔵] - 12 messages
   Создана: 04.03.2026 14:30
   Обновлена: 04.03.2026 15:45

Используйте /resume <номер> для загрузки
```

**Загрузить сессию:**
```
> /resume 1
```

**Результат:**
```
✅ Загружена сессия
✅ Загружена задача: REST API для задач
Состояние: EXECUTION 🔵
Продолжаем работу...

[State: EXECUTION] 🔵 >
```

**Важно:** Агент **НЕ** будет повторять вопросы! Он помнит:
- Стек (Express.js, TypeScript)
- План
- Текущий этап выполнения

## 💻 Команды управления задачами

### `/task` - Показать текущую задачу

```
> /task
```

**Вывод:**
```
📋 Текущая задача:
Описание: Напиши REST API для управления задачами
Состояние: EXECUTION 🔵
Создана: 04.03.2026 14:30
История: START → PLANNING → EXECUTION
```

### `/task new <описание>` - Создать новую задачу

```
> /task new Добавить аутентификацию JWT
```

**Вывод:**
```
✅ Создана новая задача [ID: a3f8d2c5b1e9]
Описание: Добавить аутентификацию JWT
Состояние: PLANNING 🟡
```

### `/task list` - Список всех задач

```
> /task list
```

**Вывод:**
```
📋 Задачи:
1. REST API для задач [EXECUTION 🔵] - 04.03.2026 15:45
2. Добавить аутентификацию JWT [PLANNING 🟡] - 04.03.2026 16:00
3. Деплой на сервер [DONE 🟢] - 03.03.2026 10:30
```

### `/task load <номер>` - Загрузить задачу

```
> /task load 2
```

**Вывод:**
```
✅ Загружена задача: Добавить аутентификацию JWT
Состояние: PLANNING 🟡
Продолжаем работу...

[State: PLANNING] 🟡 >
```

### `/next` - Перейти к следующему этапу

```
[State: PLANNING] 🟡 > /next
```

**Вывод:**
```
✅ Переход: PLANNING → EXECUTION 🔵
Этап выполнения. Реализую утвержденный план...
Начинаю писать код...

[State: EXECUTION] 🔵 >
```

## 📖 Сценарии использования

### Сценарий 1: Создание и выполнение задачи

```bash
npm start

# Шаг 1: Создать задачу
> Напиши сервис авторизации
[State: PLANNING] 🟡

# Агент: Какой стек использовать?
> Node.js, Express, JWT

# Агент: Какие endpoints нужны?
> /register, /login, /refresh-token

# Агент предлагает план
# Шаг 2: Утвердить план
> Отлично, начинай
[State: EXECUTION] 🔵

# Агент пишет код...
# Шаг 3: Проверка
> Проверь код
[State: VALIDATION] 🟠

# Агент проверяет, предлагает тесты
# Шаг 4: Завершение
> Все работает
[State: DONE] 🟢
```

### Сценарий 2: Пауза и продолжение

```bash
# День 1: Начало работы
npm start
> Создай мобильное приложение для задач
[State: PLANNING] 🟡

# Обсуждение плана...
> Отлично, начинай
[State: EXECUTION] 🔵

# Агент начал писать код
# Нужно уйти
Ctrl+C

# День 2: Продолжение
npm start
> /resume
> /resume 1
[State: EXECUTION] 🔵

# Продолжаем БЕЗ повторных вопросов!
> Добавь экран настроек
[Агент продолжает писать код в контексте задачи]
```

### Сценарий 3: Работа с несколькими задачами

```bash
npm start

# Задача 1: Backend API
> Создай REST API
[State: PLANNING] 🟡
> Утверждаю
[State: EXECUTION] 🔵

# Переключиться на другую задачу
> /task new Создай фронтенд на React
[State: PLANNING] 🟡

# Работа над фронтендом...
> Утверждаю план
[State: EXECUTION] 🔵

# Вернуться к первой задаче
> /task list
1. REST API [EXECUTION 🔵]
2. Фронтенд на React [EXECUTION 🔵]

> /task load 1
[State: EXECUTION] 🔵
# Продолжаем работу над API
```

### Сценарий 4: Возврат к планированию

```bash
[State: EXECUTION] 🔵

# Во время выполнения поняли, что план нужно изменить
> Стоп, нужно изменить архитектуру

# Агент может вернуть в PLANNING, если вы попросите
# Или явно:
# (В коде EXECUTION → PLANNING разрешен)
```

## ❌ Что НЕ сработает

### Попытка перепрыгнуть этапы

```
[State: PLANNING] 🟡 > Сразу переходи к проверке
```

**Результат:** Агент напомнит, что сначала нужно утвердить план и выполнить его.

### Переход в недопустимое состояние

```
[State: DONE] 🟢 > /next
```

**Результат:**
```
✅ Задача уже в финальном состоянии DONE 🟢
```

## 🔧 Технические детали

### Где хранятся данные

- **Задачи:** `.task-state/<taskId>.json`
- **Сессии:** `.chat-history/session-<timestamp>-<id>.json`

### Формат файла задачи

```json
{
  "taskId": "a3f8d2c5b1e9",
  "description": "Напиши REST API",
  "currentState": "execution",
  "startedAt": "2026-03-04T14:30:00Z",
  "updatedAt": "2026-03-04T15:45:00Z",
  "stateHistory": [
    {
      "from": "START",
      "to": "planning",
      "timestamp": "2026-03-04T14:30:00Z"
    },
    {
      "from": "planning",
      "to": "execution",
      "timestamp": "2026-03-04T15:00:00Z",
      "reason": "Plan approved by user"
    }
  ],
  "planContent": "План: 1. Создать Express app...",
  "executionResult": "Код: import express..."
}
```

### Связь сессии и задачи

```json
// session-2026-03-04-abcd1234.json
{
  "id": "abcd1234",
  "messages": [...],
  "taskStateId": "a3f8d2c5b1e9"  // ← Ссылка на задачу
}
```

## 🆘 Решение проблем

### Задача не создалась автоматически

**Решение:** Создайте вручную:
```
> /task new Описание вашей задачи
```

### Не могу перейти к следующему этапу

**Проверьте:**
1. Текущее состояние: `/task`
2. Разрешенные переходы (см. диаграмму выше)
3. Используйте `/next` для явного перехода

### Сессия не восстановила задачу

**Проверьте:**
1. Файл задачи существует: `ls .task-state/`
2. В session.json есть `taskStateId`

### Агент повторяет вопросы после resume

**Причина:** Состояние задачи не восстановилось

**Решение:**
1. Проверьте: `/task`
2. Если задачи нет, загрузите: `/task list` → `/task load <номер>`

## 📚 Дополнительные команды

### Другие команды агента

```bash
/clear         # Очистить контекст (НЕ удаляет задачу!)
/model         # Сменить модель
/profile       # Управление профилями
/stats         # Статистика сессии
/compact       # Суммаризация контекста
```

**Важно:** `/clear` очищает контекст разговора, но НЕ удаляет задачу. Текущая задача остается активной.

## ✨ Заключение

Task State Machine превращает агента из stateless в stateful:

**Было:**
- ❌ Агент забывает контекст после паузы
- ❌ Нет структурированного процесса
- ❌ Может пропустить важные этапы

**Стало:**
- ✅ Формальные состояния задачи
- ✅ Пауза и восстановление без потери контекста
- ✅ Четкий workflow: планирование → выполнение → проверка → завершение
- ✅ История переходов
- ✅ Управление несколькими задачами

**Приятной работы с агентом! 🚀**
