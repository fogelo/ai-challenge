# Дизайн: AI-ассистент поддержки пользователей (День 33)

## Продукт

**TaskFlow** — вымышленный SaaS таск-менеджер. Тарифы: Free, Pro, Enterprise. Функции: командные доски, интеграции (Slack, GitHub), уведомления, авторизация через OAuth.

---

## Архитектура

Расширение существующего CLI-агента командой `/support <user_id>`, которая переключает агента в режим поддержки.

## Компоненты

### `crm-data/users.json`

Массив пользователей:
```json
[
  { "id": "1", "name": "Иван Петров", "plan": "Pro", "status": "active", "registered": "2024-03-15" },
  ...
]
```

### `crm-data/tickets.json`

Массив тикетов:
```json
[
  { "id": "t1", "user_id": "1", "subject": "Не работает OAuth через GitHub", "status": "open", "description": "..." },
  ...
]
```

### `for_rag/support/faq.md`

FAQ по продукту: разделы по авторизации, тарифам, интеграциям, биллингу, лимитам.

### `for_rag/support/docs.md`

Документация: функции продукта, ограничения тарифов, инструкции по настройке интеграций.

### `src/mcp/server-crm.ts`

MCP-сервер, читающий `crm-data/*.json`:

- `get_user(user_id: string)` → профиль пользователя (имя, тариф, статус)
- `get_user_tickets(user_id: string)` → список тикетов пользователя

### Skill `support`

```
Ты агент поддержки TaskFlow — SaaS таск-менеджера.
При каждом вопросе:
1. Вызови get_user и get_user_tickets для получения контекста пользователя
2. Используй контекст тикетов при ответе на конкретные жалобы
3. Опирайся на документацию продукта при общих вопросах
Отвечай кратко, дружелюбно, на языке пользователя.
```

### Команда `/support <user_id>` в Chat.tsx

- Активирует skill `support`
- Инжектирует первое системное сообщение: `"Текущий пользователь: {user_id}"` — LLM сам вызывает MCP-инструменты
- Показывает в UI: `🎧 Режим поддержки: user #<id>`
- Перед каждым запросом выполняет RAG-поиск по `for_rag/support/` и добавляет результаты в контекст
- `/support off` — выход из режима, сброс skill и user_id

## Поток данных

```
Пользователь: /support 42
  → Chat: активирует skill "support", сохраняет supportUserId="42"
  → UI: показывает "🎧 Режим поддержки: user #42"

Пользователь: "Почему не работает авторизация?"
  → Chat: RAG-поиск по for_rag/support/ → добавляет релевантные чанки в контекст
  → LLM: вызывает get_user("42") → получает профиль
  → LLM: вызывает get_user_tickets("42") → получает тикеты
  → LLM: формирует ответ с учётом тарифа, статуса и открытых тикетов
  → Chat: отображает ответ
```

## Ограничения и решения

| Ограничение | Решение |
|------------|---------|
| RAG требует Ollama для эмбеддингов | Используем существующий `RagManager` — если индекс уже построен, всё работает |
| MCP-сервер server-crm нужно собрать | Добавляем в `tsconfig`, компилируется вместе с остальными серверами |
| user_id вводится вручную | Достаточно для демо; валидация — если ID не найден, сообщаем об этом |

## Тестирование (сценарии)

1. `/support 1` + "Почему не работает авторизация?" → агент видит открытый тикет t1 и отвечает по контексту
2. `/support 3` + "Хочу перейти на Enterprise" → агент видит тариф Pro и описывает преимущества апгрейда
3. `/support off` → режим отключён, обычный чат восстановлен
4. `/support 999` → агент сообщает "пользователь не найден"
