**Дата:** 2026-03-16
**Статус:** Утверждён

## Цель

Реализовать пайплайн RAG-индексации для CLI-агента: нарезка документов на чанки, генерация эмбеддингов через Ollama, сохранение локального JSON-индекса. Интеграция в агента через команду `/rag`.

---

## Источник данных

Директория `day21/for_rag/Архитектура` — личные конспекты по книгам об архитектуре ПО:
- `Head First. Архитектура ПО/` — 24 файла + подпапка `Вопросы к ИИ/` (7 файлов) = 27 файлов итого
- `Ричардс. Фундаментальный подход к программной архитектуре/` — 3 файла
- Корень `Архитектура/` — 2 файла (`Ford...md`, `Head First. Паттерны...md`)

Итого: ~32 MD-файла, ~118KB, ~1200 строк (точное число берётся из FS при индексации).

**Определение `title`:** берётся из имени ближайшей родительской папки-книги (первый уровень ниже `Архитектура/`). Для файлов в корне `Архитектура/` — из имени самого файла.

## Типы данных

```ts
interface Chunk {
  chunk_id: string;      // уникальный ID: "{relative_path}_{index}" (без коллизий)
  source: string;        // полный путь к файлу
  file: string;          // имя файла
  title: string;         // название книги (имя папки первого уровня под Архитектура/)
  section: string;       // ближайший заголовок ## или ###; "" если нет заголовков
  strategy: 'fixed' | 'structural';
  text: string;          // текст чанка
  embedding: number[];   // вектор от Ollama
}

interface IndexFile {
  meta: {
    created_at: string;
    model: string;        // "nomic-embed-text"
    strategy: 'fixed' | 'structural';
    total_chunks: number;
  };
  chunks: Chunk[];
}

interface SearchResult {
  chunk: Chunk;
  score: number;          // косинусное сходство [0, 1]
}

interface RagConfig {
  sourcePath: string;       // путь к for_rag/Архитектура
  outputPath: string;       // путь к rag-data/
  embeddingModel: string;   // "nomic-embed-text"
  ollamaUrl: string;        // "http://localhost:11434"
  topK: number;             // кол-во результатов (по умолчанию 3)
  chunkSize: number;        // для fixed: 500
  chunkOverlap: number;     // для fixed: 100
}
```

## Два пайплайна

### Индексация (`/rag index`)

```
MD-файлы из for_rag/Архитектура
        ↓
Chunker: fixed (500 символов, overlap 100)
       + structural (по заголовкам ## и ###)
        ↓
Embedder → POST http://localhost:11434/api/embeddings
           (fallback: /api/embed для старых версий Ollama)
           модель: nomic-embed-text
        ↓
Сохранение: rag-data/index-fixed.json
           rag-data/index-structural.json
```

### Поиск (`/rag <запрос>`)

```
Текст запроса
        ↓
Embedder → вектор запроса
        ↓
Searcher → косинусное сходство по всем чанкам
        ↓
Топ-3 результата с метаданными и score
```

---

## Стратегии чанкинга

### Fixed (фиксированный)
- Размер: 500 символов
- Перекрытие (overlap): 100 символов
- Алгоритм: скользящее окно по тексту файла
- Плюс: предсказуемый размер чанков
- Минус: может разрезать предложение пополам

### Structural (структурный)
- Нарезка по заголовкам `##` и `###` в Markdown
- Каждый раздел = один чанк
- Метаданные `section` берутся из текста заголовка
- **Fallback:** если в файле нет заголовков `##`/`###` — весь файл = один чанк, `section = ""`
- Плюс: сохраняет смысловые блоки
- Минус: чанки разного размера (от 50 до 2000 символов)

## Команды агента

| Команда | Описание |
|---|---|
| `/rag index` | Индексировать все документы (обе стратегии) |
| `/rag <запрос>` | Поиск по structural-индексу (по умолчанию) |
| `/rag <запрос> --fixed` | Поиск по fixed-индексу |
| `/rag compare <запрос>` | Сравнение результатов обеих стратегий |

## Публичный API RagManager

```ts
class RagManager {
  async index(): Promise<void>
  // Индексирует все файлы из sourcePath обеими стратегиями, сохраняет JSON

  async search(query: string, strategy: 'fixed' | 'structural', topK?: number): Promise<SearchResult[]>
  // Возвращает topK результатов по косинусному сходству

  async compare(query: string): Promise<{ fixed: SearchResult[]; structural: SearchResult[] }>
  // Возвращает результаты обеих стратегий для сравнения
}
```

## Интеграция в существующий код

- `RagManager` инициализируется один раз в `Chat.tsx` через `useRef` (аналогично другим менеджерам)
- Обработчик `/rag` добавляется в switch-блок команд рядом с `/task`, `/invariants`
- Индексация (`/rag index`) — асинхронная операция; пока идёт, показывается сообщение "⏳ Индексирую документы..."
- При недоступности Ollama (`ECONNREFUSED`) показывается: `❌ Ollama не доступен. Запустите: ollama serve`
- Никакие существующие модули не изменяются

## Ограничения

- Ollama должен быть запущен (`ollama serve`) перед использованием `/rag`
- Индекс нужно пересобирать вручную (`/rag index`) при изменении документов
- JSON-формат подходит для текущего объёма (~29 файлов), не для production
