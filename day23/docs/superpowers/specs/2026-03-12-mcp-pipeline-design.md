# MCP Pipeline — Дизайн (Day 19)

## Цель

Реализовать три MCP-инструмента (`search`, `summarize`, `saveToFile`) и продемонстрировать их автоматическую цепочку под управлением LLM.

## Инструменты

### `search(url: string)`
- Поддерживает только HTTPS (Node.js `https` модуль уже импортирован в server.ts)
- HTTP URLs не поддерживаются — это принятое ограничение для демо
- HTTP GET запрос по URL, очистка HTML через регексы (без новых зависимостей):
  - Удаляем `<script>`, `<style>`, `<noscript>` блоки целиком
  - Удаляем все HTML-теги
  - Декодируем базовые HTML-сущности (`&amp;`, `&lt;` и т.д.)
  - Схлопываем пробелы и переносы строк
- Обрезка до 8000 символов
- Возвращает: чистый текст страницы

### `summarize(text: string, instructions?: string)`
- Вызывает OpenRouter API с ключом из `process.env.OPENROUTER_API_KEY`
- MCP-сервер запускается как дочерний процесс и наследует env родителя → `OPENROUTER_API_KEY` доступен
- Модель: `google/gemini-flash-1.5` (быстрая и дешёвая)
- Промпт: краткое резюме текста в 3–5 предложениях
- `instructions` — опциональные дополнения (язык, фокус)
- **Таймаут**: нет — принятое ограничение для демо; LLM-вызов может занять 10–30 сек
- Возвращает: готовый текст резюме

### `saveToFile(filename: string, content: string)`
- Папка: `<project-root>/output/` (создаётся автоматически через `fs.mkdir`)
- Путь разрешается относительно `process.cwd()` при запуске CLI из корня проекта
- Нет ограничения на размер файла — принятое ограничение для демо
- Возвращает: полный путь к файлу

## Поток данных

```
User: "Возьми [url], суммаризируй и сохрани в [filename]"

LLM → search({ url })                         → текст страницы (≤8000 символов)
LLM → summarize({ text })                     → краткое резюме (3–5 предложений)
LLM → saveToFile({ filename, content })       → путь к файлу
```

Tool-calling loop в `Chat.tsx` (строки ~1607) уже обрабатывает многошаговые цепочки:
передаёт результат каждого вызова как `role: 'tool'` сообщение в следующий запрос к LLM.
