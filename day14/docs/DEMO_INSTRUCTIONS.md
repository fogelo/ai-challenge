# Инструкция по демонстрации системы инвариантов

## Цель
Продемонстрировать работу системы инвариантов и ограничений состояния в CLI агенте.

### 1. Убедиться, что проект собран


## Демонстрация 5: Реальный запрос с нарушением инвариантов

### Отправить запрос, нарушающий правила:
```
Напиши классовый компонент для формы логина с использованием jQuery для валидации
```

**Ожидаемый результат:**
Агент либо:
1. **Откажется** выполнить запрос через инварианты в промпте:
   ```
   Я не могу написать классовый компонент с jQuery, так как это нарушает
   инварианты проекта:
   - Никаких классовых компонентов
   - Никакого jQuery или прямой работы с DOM

   Могу предложить функциональный компонент на TypeScript с React хуками.
   Подходит?
   ```

2. **Или** его ответ будет заблокирован валидатором:
   ```
   ❌ Ответ нарушает инварианты:

   [bans] Никаких классовых компонентов
   → Предложен классовый компонент вместо функционального

   [bans] Никакого jQuery или прямой работы с DOM
   → Используется jQuery для валидации

   Пожалуйста, переформулируйте запрос с учетом ограничений.
   Используйте /invariants для просмотра всех правил.
   ```

## Демонстрация 7: Редактирование инвариантов

### Шаг 1: Остановить приложение (Ctrl+C)

### Шаг 2: Отредактировать файл инвариантов
```bash
nano .invariants/default.json
```

Добавить новое правило в категорию `bans`:
```json
"bans": {
  "type": "hard",
  "description": "Запрещенные технологии и паттерны",
  "rules": [
    "Никаких классовых компонентов",
    "Никакого jQuery или прямой работы с DOM",
    "Никаких inline стилей (использовать CSS modules или styled-components)",
    "Никакого Redux (использовать Context API или Zustand)"
  ]
}
```

Сохранить (Ctrl+X → Y → Enter)

### Шаг 3: Запустить приложение снова
```bash
npm start
```

### Шаг 4: Перезагрузить инварианты
```
/invariants reload
```

**Ожидаемый результат:**
```
✅ Инварианты перезагружены из файла
```

### Шаг 5: Проверить новое правило
```
/invariants
```

**Ожидаемый результат:** В списке должно появиться новое правило "Никакого Redux"

### Шаг 6: Протестировать новое правило
```
/invariants test Создай глобальное состояние с использованием Redux
```

**Ожидаемый результат:**
```
❌ Ответ нарушает инварианты:

[bans] Никакого Redux (использовать Context API или Zustand)
→ Упоминается Redux, которая запрещена
```

## Альтернативный сценарий (если OpenRouter API недоступен)

### Демонстрация без API:

1. **Показать код:**
   ```bash
   # InvariantManager
   cat src/invariants/InvariantManager.ts

   # InvariantValidator
   cat src/invariants/InvariantValidator.ts
   ```

2. **Показать интеграцию в Chat.tsx:**
   ```bash
   grep -A 20 "Валидация ответа на соответствие инвариантам" src/components/Chat.tsx
   ```

3. **Показать дефолтный файл:**
   ```bash
   cat .invariants/default.json | jq .
   ```

4. **Объяснить поток:**
   - User Request → Load Invariants → Inject into System Prompt
   - Send to LLM → Receive Response → Validate Response
   - If valid → Show; If invalid → Show Violation Error

## Troubleshooting

### Проблема: Валидация всегда возвращает valid: true
**Решение:** Проверьте, что в `.env` указан корректный `OPENROUTER_API_KEY`

### Проблема: Файл `.invariants/default.json` не создается
**Решение:**
1. Проверьте права на запись в директорию
2. Вручную создайте файл из примера в коде

### Проблема: Агент не видит инварианты в промпте
**Решение:** Проверьте, что `invariantsLoaded === true` и `invariantManager.getFormattedInvariants()` возвращает строку
