# Дизайн: Персонализация агента

**Дата:** 2026-03-03
**Задача:** День 12 - Добавление персонализации поверх модели памяти

## Обзор

Реализация системы персонализации CLI агента через управление множественными профилями пользователей. Каждый профиль содержит предпочтения по стилю общения, техническому стеку и контексту использования, которые автоматически применяются ко всем запросам.

## Цели

1. ✅ Создать профиль пользователя с расширенным набором параметров
2. ✅ Описать предпочтения (стиль, формат, ограничения, контекст)
3. ✅ Подключить профиль к каждому запросу через system prompt
4. ✅ Обеспечить разные ответы для разных профилей
5. ✅ Автоматическое применение персонализации без явного указания

## Архитектура

### Новые компоненты

#### ProfileManager (`src/profile/ProfileManager.ts`)
Центральный компонент для управления жизненным циклом профилей.

**Методы:**
- `initialize()` - инициализация, проверка наличия профилей
- `listProfiles()` - список всех профилей
- `getActiveProfile()` - получить активный профиль
- `createProfile(profile: UserProfile)` - создать новый профиль
- `switchProfile(name: string)` - переключить активный профиль
- `updateProfile(name: string, updates: Partial<UserProfile>)` - обновить профиль
- `deleteProfile(name: string)` - удалить профиль
- `hasProfiles()` - проверка наличия профилей (для интервью)

**Хранение:**
- `.memory/profiles/<profile-name>.json` - файл профиля
- `.memory/profiles/.active` - имя активного профиля

#### InterviewFlow (`src/profile/InterviewFlow.ts`)
Компонент для проведения интервью при создании профиля.

**Вопросы интервью:**
1. Имя профиля (по умолчанию "default")
2. Для чего будете использовать агента? (context.purpose)
3. Предпочитаемый стиль ответов? (краткий/подробный)
4. Тон общения? (формальный/разговорный)
5. Включать примеры кода? (да/нет)
6. Основной стек технологий? (можно пропустить)
7. Предпочитаемый язык программирования? (можно пропустить)
8. Уровень детализации? (минимальный/средний/максимальный)

**Особенности:**
- Можно пропустить интервью (skip/Ctrl+S) → создается default профиль
- Автоматический запуск при первом старте без профилей
- Сохранение и активация профиля после завершения

### Структура данных

```typescript
interface UserProfile {
  name: string;

  // Стиль общения
  responseStyle: 'краткий' | 'подробный';
  tone: 'формальный' | 'разговорный';
  includeCodeExamples: boolean;
  detailLevel: 'минимальный' | 'средний' | 'максимальный';

  // Контекст использования
  context: {
    purpose: string;     // "изучение JavaScript", "разработка Android"
    domain: string;      // "программирование", "обучение"
    goals: string[];     // ["подготовка к собеседованию", "pet-проект"]
  };

  // Технические предпочтения
  stack: string[];
  preferredLanguage: string;

  // Ограничения
  constraints: {
    forbidden: string[];  // Запрещенные технологии/паттерны
    required: string[];   // Обязательные требования
    rules: string[];      // Правила и рекомендации
  };
}
```

### Интеграция с существующим кодом

**MemoryManager:**
- Получает ссылку на `ProfileManager`
- При инициализации проверяет наличие профилей
- Загружает активный профиль в `LongTermMemory`

**LongTermMemory:**
- Обновляется при переключении профиля
- `profile` и `constraints` берутся из активного профиля

**Chat.tsx:**
- Новые команды для управления профилями
- System prompt формируется с учетом активного профиля

## Поток данных

### При запуске приложения

```
App Start
  ↓
MemoryManager.initialize()
  ↓
ProfileManager.initialize()
  ↓
Есть профили?
  ↓
  НЕТ → InterviewFlow.start()
        → Создание профиля (или skip → default)
        → ProfileManager.createProfile()
  ↓
  ДА → ProfileManager.loadActive()
  ↓
Активный профиль → LongTermMemory
  ↓
Приложение готово
```

### При отправке сообщения

```
User input
  ↓
Conversation.buildSystemPromptWithMemory()
  ↓
MemoryManager.getContextForPrompt()
  ├─ shortTerm (история)
  ├─ working (задача)
  └─ longTerm
      ├─ profile ← из активного профиля
      ├─ constraints ← из активного профиля
      └─ knowledge (факты)
  ↓
System prompt с персонализацией
  ↓
LLM API
  ↓
Персонализированный ответ
```

### При переключении профиля

```
/profile switch <name>
  ↓
ProfileManager.switchProfile(name)
  ↓
ProfileManager.getProfile(name)
  ↓
LongTermMemory обновляется
  ↓
Следующие запросы используют новый профиль
```

## Команды

Новые команды в Chat.tsx:

- `/profile create` - создать новый профиль через интервью
- `/profile list` - показать все профили (имя, активный)
- `/profile switch <name>` - переключить активный профиль
- `/profile show` - показать активный профиль (существующая)
- `/profile edit <field> <value>` - редактировать поле активного профиля
- `/profile delete <name>` - удалить профиль (с проверками)

## Обработка ошибок

### Инициализация
- **Поврежденный файл профиля:** Логирование + создание default профиля
- **Несуществующий активный профиль:** Выбор первого доступного

### Интервью
- **Прерывание:** Сохранение draft профиля для продолжения
- **Невалидный ввод:** Повторный запрос с подсказкой

### Операции с профилями
- **Профиль не найден:** Уведомление с предложением `/profile list`
- **Удаление активного:** Запрет с предложением переключиться
- **Удаление последнего:** Запрет операции
- **Ошибка записи:** Попытка альтернативного пути сохранения

**3. Автоматическое применение constraints**
