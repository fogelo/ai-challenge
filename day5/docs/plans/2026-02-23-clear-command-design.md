# Дизайн команды /clear для очистки контекста

**Дата:** 2026-02-23
**Статус:** Утверждено

## Обзор

Добавление команды `/clear` для сброса контекста диалога и статистики сессии, при сохранении видимой истории сообщений на экране.

## Цели

- Позволить пользователю начать новый диалог с чистым контекстом без перезапуска приложения
- Сбросить накопительную статистику сессии и метрики последнего ответа
- Сохранить видимую историю сообщений на экране для справки

## Требования

### Функциональные

1. Команда `/clear` очищает внутренний контекст диалога (массив сообщений в объекте Conversation)
2. Сбрасывает статистику сессии (totalTokens, totalCost, requestCount и т.д.) в нулевые значения
3. Убирает метрики последнего ответа
4. Показывает уведомление: "Контекст и статистика очищены. История сообщений сохранена на экране."
5. НЕ очищает видимую историю сообщений в UI (массив `messages` state)
6. Следующий запрос к API отправляется с пустой историей

### Нефункциональные

- Команда должна работать мгновенно
- Не должна вызывать ошибок
- Должна быть идемпотентной (можно вызывать повторно без побочных эффектов)

## Архитектура

### Изменяемые компоненты

**Файл:** `src/components/Chat.tsx`

**Добавляемый код:**

```typescript
if (trimmed === '/clear') {
  conversation.clear();
  setSessionStats({
    totalTokens: 0,
    totalPromptTokens: 0,
    totalCompletionTokens: 0,
    totalCost: 0,
    requestCount: 0,
  });
  setLastResponseMetrics(null);
  setNotification('Контекст и статистика очищены. История сообщений сохранена на экране.');
  return true;
}
```

### Используемые существующие ресурсы

- `conversation.clear()` - метод класса Conversation (src/chat/conversation.ts:18-20)
- `sessionStats` state - уже определён
- `lastResponseMetrics` state - уже определён
- `setNotification()` - функция для показа уведомлений

## Поток данных

1. Пользователь вводит `/clear` и нажимает Enter
2. `useInput` хук получает ввод, вызывает `handleCommand(userInput)`
3. `handleCommand` проверяет `trimmed === '/clear'`
4. Выполняются действия:
   - `conversation.clear()` - очищает внутренний массив messages
   - `setSessionStats({...})` - сбрасывает статистику
   - `setLastResponseMetrics(null)` - убирает метрики
   - `setNotification(...)` - показывает уведомление
5. Функция возвращает `true` (команда обработана)
6. UI перерисовывается:
   - Старые сообщения остаются видимыми
   - Секция статистики исчезает
   - Появляется уведомление
7. Следующий запрос к API получает пустую историю через `conversation.getHistory()`

### Важное замечание

После `/clear` существует намеренное расхождение между:
- Видимой историей (`messages` state) - остаётся заполненной
- Историей для API (`conversation.getHistory()`) - становится пустой

Это желаемое поведение, позволяющее пользователю видеть прошлый разговор, но начать новый контекст с моделью.

## Обработка ошибок и граничные случаи

### Граничные случаи

1. **Вызов `/clear` при пустой истории**
   - Поведение: Команда выполняется нормально
   - Обоснование: Операция идемпотентна и безопасна

2. **Вызов `/clear` во время загрузки (isLoading === true)**
   - Поведение: Команда игнорируется
   - Обоснование: Проверка `if (isLoading) return` в useInput (строка 213)

3. **Регистр команды**
   - Только `/clear` (нижний регистр) работает
   - Соответствует существующему поведению других команд

### Обработка ошибок

Операции не могут вызвать ошибки:
- `conversation.clear()` - простая операция с массивом
- React state setters не бросают исключений
